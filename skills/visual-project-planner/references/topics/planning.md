# 先研究，再组织读者的决定

按行为分成一至五条主要变化；每条包含现状、目标、理由、来源与验收。文件名放依据层，实施顺序单列。不能为了视觉上的简洁删除迁移、兼容、数据或授权边界。

新建：先界定谁使用、何时使用、成功结果，再画目标路径。修改：读取实现、入口、依赖、测试与现有规划；在同一关系图中解释哪里变化。保留明确的原有保证。

提问标准：答案改变范围、外部行为、成本或不可逆取舍，且无法从现有上下文推断。每题给推荐选项与各自代价。零个决策也成立。已经授权的实施不因生成页面而再次索要确认。

证据：verified 仅用于已读事实；inferred 附推断依据；proposed 用于拟议行为。记录文件的相对位置或公开来源，必要时 baseline 保存读取时的文件 SHA256。源代码变动后重新核对，不把旧引用当新事实。

案例：增加批量输入，一级条目是“支持一批输入且保留单项用法”，其下再说明参数、错误处理与文件。反例：把“修改三个文件”当三条用户行为；把未实现能力写成已存在能力。
