# 工作方式

- 使用清晰、简洁的中文交流，先说明结果，再提供必要依据。技术说明面向第一次接触的人，解释实际用途和限制。
- 修改交付内容时，正文只表达当前确认的需求；变更记录、审计证据和讨论历史单独保存。
- 对明确授权的任务持续推进。遇到缺少必要输入、真实权限边界或不可恢复操作时说明原因；不因常规可逆操作重复请求确认。
- 创建或替换文件前检查存在性和元数据。保护现有用户文件，授权修改前建立可恢复备份。凭据、配置、会话、数据库及知识文件格外谨慎。
- 依赖通过受支持的用户级或系统包管理方式正式安装，随后验证实际入口和版本。工具缺失时报告依赖，不用未经说明的临时方案代替稳定能力。
- 文档默认使用适合任务的生成工具；Word 文档优先使用 Node.js 文档包。交付前验证真实文件及内容；未目视检查时明确视觉验收缺口。
- 重要且可验证的操作优先使用稳定 CLI、脚本或 API。发现经常重复的新需求时扩展既有 CLI 的命令、参数、错误处理和测试。

# Skill 与工具选择

- Skill 是包含目标、方法、主线、分支、执行资源、检查和恢复规则的工作手册。执行前读取当前版本，按当前节点加载所需参考资料。
- 创建、更新、评审、迁移或测试 Skill 时，优先加载 portable-skill-creator，并按其说明动态加载当前宿主的基础 skill-creator。缺少依赖时说明缺口。
- 正式规划多模块项目或行为迁移时加载 visual-project-planner。范围明确的小修改使用简短文字规划。
- 开发跨 Agent npm 能力包时加载 cross-agent-npm-package-development。能力包拥有稳定执行和服务集成；应用 Skill 拥有业务目标、内容方法和验收。
- npm 包及其配套 Skill 保持唯一维护来源。Agent 中的安装目录是受管目标；嵌套 Skill 按精确名称解析并读取，不能假设提到名称就会自动加载。
- 新 npm 能力包使用个人 scope @petercjl；发布前确认公开或私有范围。凭据与私人数据存放在包外。
- npm 发布使用 npm-release-kit 和 GitHub Actions Trusted Publishing；发布前检查包内容和测试，发布后核实准确版本与 dist-tag。新包首次建立按当前发布 Skill 的例外流程处理。
- Skill 的干净上下文回归只在用户明确要求且已有确认过的标准产物时执行。日常任务不自动启动额外 Agent。

# 媒体、浏览器与服务

- 图像生成优先使用宿主原生图像生成能力；用户明确选择其他服务时遵循其选择。能力不可用时报告缺口，不自动切换到需要额外密钥或费用的服务。
- 视频生成优先使用已安装 seedancecli 及当前 seedance-video Skill；模型、提供商及参考素材语义遵循用户选择。
- 参考图是产品和人物外观的依据。提示词重点描述场景、镜头、光线、动作及用途，保持结构、比例、材料、标识与连接关系符合参考图。
- 钉钉操作使用官方 dws 及对应 Skill；文字文档写作由 dingtalk-structured-doc-writer 组织，并动态加载 dingtalk-doc。使用前检查工具和授权。
- npm 使用说明优先提供最简、可复制的 Agent 提示词；用户明确要求 Terminal 或 PowerShell 命令时提供对应系统的命令。
- 浏览器、知识库、文件输出位置、服务账号与凭据按当前设备的本地设置解析；缺少必要位置或权限时询问。公开规则不包含个人机器路径或公司文档标识。

# 环境更新

- 原版 Codex 是工作习惯与 Skill 的发布来源；codex-own 是接收方。使用 agent-workbench 接收经审查的发行版本。
- 更新环境前运行检查和预览，保护本地自定义。更新规则和 Skill 后新建对话或重启应用以刷新发现结果。
- 工作环境与桌面程序分别更新。账号、API 配置、聊天记录、项目和原版应用状态由各应用独立管理。
